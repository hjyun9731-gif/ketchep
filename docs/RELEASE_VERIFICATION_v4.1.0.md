# v4.1.0 배포 전 확인 기록

## 이번 요구사항 반영

- 회원 수정: 공문주소 별도유지 체크박스 제거, 주소 입력행 압축
- 가입표시 O/가입 + 실제 가입일 없음: 가입상태는 유지하고 `가입일자 미상`으로 표시, 임의 가입일 생성 금지
- 폐업/양도/이관: 명단 행에서 단일 `폐업·양도·이관` 버튼 → 처리선택 모달 → 후속 모달
- 양도: 강원도 내 양도양수 전용 모달로 통일
- 폐업: 불필요한 환불문자 체크박스 제거, 현재 미수금/신규 부과중지 결과 표시
- 카드결제: 실제 알토란/사이다페이 헤더 별칭 반영
- 미수금: 지역/계정/미수·완납/최소금액/최대금액 필터 추가
- 입금대조: BankTransaction에서 존재하지 않는 카드사 표시 필드 호출 제거
- 농협 붙여넣기: 헤더 추론 실패 시 작은 순번값보다 실제 금액 규모 열을 우선하도록 보완
- 발송닷컴: 자격정보를 코드에 넣지 않고 Railway 환경변수에서만 읽도록 유지

## 실제 첨부 카드파일 구조 확인

### 알토란 `07.09(2).xlsx`
확인된 주요 열:
- 고객조회번호 → 거래 식별값
- 거  래  처 → 차량번호
- 수납월일 → 결제일
- 수납금액 → 회원 총결제금액
- 이체일 → 정산일
- 이체금액 → 순정산액
- 수수료 → 수수료

검증 예시:
- 80배 1004 / 총결제 60,000 / 순정산 59,920 / 수수료 80
- 81배 1950 / 총결제 45,000 / 순정산 44,920 / 수수료 80

### 사이다페이 `결제리스트.xls`
확인된 주요 열:
- 주문번호 → 거래 식별값
- 완료일시 → 결제일시
- 판매금액 → 회원 총결제금액
- 정산일시 → 정산일
- 정산금액 → 순정산액
- 구매자명 → 이름
- 고객번호 → 차량번호/고객번호
- 결제상태 → 결제완료/결제취소 판정

`결제취소`, `취소완료`, `승인취소`는 회원 미수금에 반영하지 않도록 처리한다.

## 보안 확인

- 발송닷컴 아이디/비밀번호 실제 값은 ZIP, 소스코드, 문서에 포함하지 않음.
- `BALSONG_USER_ID`, `BALSONG_USER_PW`, `BALSONG_CALLBACK` 환경변수명만 포함.

## 검증 한계

- Python 전체 구문 검사는 통과.
- 현재 작업 환경에는 Django가 설치되어 있지 않아 Django template engine 및 Railway 운영 DB를 이용한 실제 HTTP 실행 테스트는 수행하지 못함.
- 따라서 Railway 배포 후 연결확인/시험발송/실제 파일 업로드를 한 번씩 확인해야 함.
