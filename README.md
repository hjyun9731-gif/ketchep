# 화물협회 미수금·입금대조 웹프로그램

엑셀로 관리하던 회원, 협회비·관리비 부과, 통장 입금대조, 카드 결제, 미수금 문자, 폐업·환불, 내용증명 이력을 하나의 웹 시스템에서 처리하는 Django 애플리케이션입니다.

## 구현된 주요 기능

- 월별 작업 및 다중 버전 관리
  - `2026년 7월 1차 작업`, `2차 작업`, `최종본` 형태
  - 같은 유형 파일을 다시 올리면 기존 파일을 덮어쓰지 않고 새 버전 자동 생성
  - 이전 버전의 부과·입금 매칭을 새 버전에 이어서 적용
- 7종 Excel 업로드
  - 미수금, 통장 1·2·3, 전체면허자현황, 알토란, 사이다페이
  - `.xlsx`와 구형 `.xls` 지원
  - 열 자동 감지 및 사용자 열 매핑
- 회원·차량 관리
  - 주민등록번호 앞 6자리, 휴대전화, 기본주소, 공문주소, 비고, 지역
  - 현재 차량 1대 및 과거 차량번호 이력
  - 결번·수신거부·주소 확인 필요 상태
  - 폐업·재등록, 협회 가입·탈퇴 이력
  - 가족·직계 승계 시 회계원장과 미수금 승계, 일반 양도양수 시 이전 명의자 미수금 유지
- 부과 규칙
  - 협회비와 관리비를 동시에 부과하지 않음
  - 2026년까지 택배 `배` 비가입 차량 관리비 5,000원
  - 2027년 1월부터 기존 비가입자 전원 매월 1일 관리비 5,000원
  - 2027년 이후 신규 비가입자는 자격증명 발급일 한 달 뒤 같은 날짜부터 관리비 부과
  - 협회비 10,000원, 만 70세가 되는 해 1월부터 5,000원
  - 폐업월·재등록월 부과 제외
  - 가입일 한 달 뒤 같은 날짜부터 협회비 부과
- 수수료 규칙
  - 비가입 일반차량: 자격증명 50,000원, 대폐차 30,000원
  - 비가입 택배 `배`: 자격증명 30,000원, 대폐차 면제
  - 협회 가입자: 자격증명·대폐차 모두 면제
- 입금대조
  - 전체 차량번호 → 이름+차량 일부 → 고유 이름 순서로 자동매칭
  - 동명이인·일반이체·지로 등은 확인 필요
  - 한 입금을 여러 회원 및 여러 계정으로 분할
  - 잘못 배정한 입금 취소·재배정 및 원상복구
  - 가장 오래된 미수금부터 자동 충당
  - 일부납부와 선납금 자동 처리
  - 알토란·사이다페이 총결제액은 회원 미수금에 반영하고 통장 순정산액은 이중 반영하지 않음
- 문자
  - 발송닷컴 LMS 연동
  - 일반 미수금, 폐업 미수금, 환불 안내, 환불 완료 템플릿
  - 미리보기, 대상 체크 해제, 즉시·예약 발송, 실패 건 재발송
  - 발송 직전 최신 미수금·환불금액·환불일·전화번호 재확인
  - 결번·수신거부·번호 없음 자동 제외
  - 같은 날 성공 발송된 미수금 문자는 중복 차단
- 폐업·환불
  - 폐업월 부과 취소
  - 선납금이 있으면 환불대기 생성
  - 은행명·계좌번호·예금주·환불일·방법·메모 저장
  - 환불 안내 및 완료 문자
- 내용증명
  - 기본주소, 공문주소, 두 주소 모두 선택
  - 등기번호와 배송상태 기록
  - 반송·수취인불명·주소불명·폐문부재 시 주소 확인 필요 자동 전환
- Excel 출력
  - 선택 월 결과와 전체 누적 현황
  - 미수금, 입금 처리, 확인 필요, 선납금, 폐업·환불, 회원정보, 통장 원본, 연락 이력 시트
  - 다운로드 시점의 최신 내용으로 생성
- 변경이력
  - 주요 수정 전후 값을 `admin` 작업자로 저장

## 로컬 실행

Python 3.12 이상을 권장합니다.

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
cp .env.example .env
python manage.py migrate --run-syncdb
python manage.py bootstrap_admin
python manage.py seed_defaults
python manage.py runserver
```

접속 주소: `http://127.0.0.1:8000/`

기본 계정:

- 아이디: `admin`
- 비밀번호: `admin1234`

## Railway 배포

1. 이 폴더를 GitHub 저장소에 올립니다.
2. Railway에서 GitHub 저장소를 연결합니다.
3. PostgreSQL 서비스를 추가합니다.
4. 아래 환경변수를 등록합니다.
5. 업로드 원본을 계속 보관하려면 Railway Volume을 추가하고 `MEDIA_ROOT=/data/media`로 설정합니다.
6. 배포하면 `railway/start.sh`가 데이터베이스 초기화, 관리자 생성, 기본 템플릿 생성 후 Gunicorn을 실행합니다.

필수 또는 권장 환경변수:

```text
DJANGO_SECRET_KEY=<긴 임의 문자열>
DJANGO_DEBUG=0
DJANGO_ALLOWED_HOSTS=<Railway 도메인>
CSRF_TRUSTED_ORIGINS=https://<Railway 도메인>
DJANGO_ADMIN_USERNAME=admin
DJANGO_ADMIN_PASSWORD=admin1234
ASSOCIATION_NAME=<협회명>
ASSOCIATION_PHONE=<협회 전화번호>
MEDIA_ROOT=/data/media
SECURE_SSL_REDIRECT=1
```

PostgreSQL의 `DATABASE_URL`은 Railway 연결 시 자동 주입할 수 있습니다.

### 발송닷컴 연동

Railway Variables에만 입력하고 GitHub나 채팅에 올리지 않습니다.

```text
BALSEONG_USER_ID=<발송닷컴 아이디>
BALSEONG_USER_PW=<발송닷컴 비밀번호>
BALSEONG_CALLBACK=<등록된 발신번호>
BALSEONG_DRY_RUN=0
```

처음에는 `BALSEONG_DRY_RUN=1`로 화면과 발송대상을 검증한 뒤, 발송번호 등록 상태를 확인하고 1건 시험 발송 후 `0`으로 변경하는 방식이 안전합니다.

### 예약 문자 실행

별도 Railway Cron 서비스에서 다음 명령을 5분 간격으로 실행하도록 설정합니다.

```bash
bash railway/send_scheduled_messages.sh
```

예시 Cron 표현식:

```text
*/5 * * * *
```

## 파일 업로드 사용 순서

1. 월 작업을 만듭니다.
2. 전체면허자현황을 먼저 올립니다.
3. 미수금 파일을 올립니다.
4. 통장 1·2·3과 알토란·사이다페이를 올립니다.
5. 자동 열 감지가 실패한 파일은 `열 매핑`에서 실제 열을 지정합니다.
6. `전체 분석 실행`을 누릅니다.
7. `입금대조`에서 확인 필요·중복 의심·미배정 건을 수정합니다.
8. 최종확정 후 월별 Excel을 내려받습니다.

`전체 분석 실행`은 전체면허자현황 → 미수금 → 통장 → 카드 순서로 반영합니다.

## 운영상 주의

- 공용 계정 정책에 따라 모든 변경이력은 `admin`으로 기록됩니다.
- 이미 PC에 내려받은 Excel은 자동 변경되지 않습니다. 수정 후 다시 다운로드해야 최신 내용이 반영됩니다.
- 발송닷컴 실제 결과 확인 방식은 협회 계정의 API 응답 형식으로 1건 시험한 뒤 최종 조정해야 합니다.
- 업로드 파일의 열명이 업체·은행마다 다르면 최초 1회 열 매핑이 필요합니다.
- 이 저장소는 첫 배포 시 `migrate --run-syncdb`로 업무 테이블을 생성합니다. 실제 운영 스키마가 확정되면 정식 Django migration 파일을 생성해 버전 관리하는 것이 좋습니다.
